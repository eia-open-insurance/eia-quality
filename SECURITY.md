# Security policy

## Reporting a vulnerability

Prefer GitHub private vulnerability reporting on the affected repository.

If private reporting is unavailable, email `support@rmburgess.com`.

Do not open a public issue for a suspected vulnerability.

Include:

- affected repository and version or commit;
- vulnerability type and impact;
- reproduction steps or proof of concept;
- suggested remediation, if known;
- whether you wish to be credited.

## Response

The security team acknowledges within two business days and provides a remediation plan for confirmed findings. Critical findings are handled under the incident process.

## Disclosure

We aim to disclose within 90 days of a fix, coordinated with the reporter. We will credit reporters unless they ask to remain anonymous.

## Safe harbor

Good-faith security research is welcome. Do not access, modify, or exfiltrate data that is not yours, and do not test against production without written authorization.

## Supported versions

There is no production release yet. Supported versions will be listed here when the first release is published.
